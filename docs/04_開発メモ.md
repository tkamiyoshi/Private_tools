## 2. 実装上の判断
- **ES5寄りの記法**を採用（`var` / `function`）。古いタブレット端末のブラウザでも動くようにするため。テンプレートリテラルとアロー関数は本体では使用しない。
- **タイルは絶対配置**：パズルのタイルを `position:absolute` で座標指定し、`left/top` のトランジションで滑らかに動かす。グリッドの下敷き（`.cell`）は別要素で常時表示。
- **スワイプ中のスクロール抑止**：盤面の `touchmove` のみ `preventDefault()`。`touch-action:none` も併用。ページ全体のスクロールは阻害しない。
- **タブは表示切替のみ**：各機能はDOMに常駐しており、タブを移動しても状態（電卓の途中式、ストップウォッチの計測、パズルの盤面）は保持される。
- **`aspect-ratio`** でパズル盤・カレンダーのマスを正方形に。画面幅に追従する。
- **パズルの描画タイミング**：非表示中は `clientWidth` が0になり座標計算ができないため、タブ表示時と `resize` 時に再描画する。

## 3. 実装中に見つけて直した点
| # | 内容 | 対応 |
|---|---|---|
| 1 | 1024達成時に「もういちど」しか選べず、続きが遊べなかった | オーバーレイに「このまま つづける」ボタンを追加（達成時のみ表示） |
| 2 | すうじタッチのベストタイムが0秒扱いで表示されなくなる境界 | 未記録は `null` で管理し、`0` と区別 |
| 3 | ストップウォッチのラップが計測直後に効かない | 判定を「経過0ms」から「未スタート」に変更 |
| 4 | ストップウォッチの初期表示がHTML直書き頼りだった | JS起動時にも `00:00.00` を設定 |

## 4. 動作確認方法
```
index.html をダブルクリック（またはブラウザにドラッグ＆ドロップ）
```
サーバー不要・通信不要。スマホ/タブレットへはファイルを共有するか、任意のWebサーバーに置く。

## 5. テストの実行
```
node tests/test.js
```

## 6. 追加修正（版1.1 / 検証部の指摘3点の再確認時）
| # | 内容 | 対応 |
|---|---|---|
| 5 | 1024達成オーバーレイの表示中も入力が盤面に届き、見えないまま盤面が動いた | `move()` の先頭でオーバーレイ表示中の入力を無視 |
| 6 | ストップウォッチのラップ判定が「経過0ms」に依存し、停止直後などに効かない場合があった | `started` フラグ（一度でもスタートしたか）で判定 |

指摘の3点はいずれも版1.0で修正済みだったが、再確認の過程で上記2件を追加で発見・修正し、
`tests/test.js` に3点それぞれの回帰テスト（T11、15ケース）を追加した。
1024到達の検証は乱数を固定したうえで先読み探索ボットに実際にプレイさせており、毎回同じ結果になる。
